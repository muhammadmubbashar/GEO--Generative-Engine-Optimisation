1. Making Flight Centre information easier for AI to use

We are presenting our Semester Two work for Flight Centre Travel Group. Each member will briefly introduce themselves as their section begins. Flight Centre wanted to understand how its travel products could become more visible and relevant in AI-assisted shopping. We built and tested a page-improvement prototype. Our main question is simple: when an AI already has Flight Centre information alongside competitors, does a clearer page make it more likely to cite Flight Centre? We will show the system, the page changes, a saved demonstration and the results. The talk is twenty minutes, followed by five minutes for questions.

2. What we measured

Imagine an answer that gives travel information and places a small source number next to it. If that number points to a Flight Centre page, we count the answer as citing Flight Centre. We count the answer once, even if it includes several Flight Centre references. This is one part of the larger customer journey. Finding a page, citing it, recommending the business and making a booking are different outcomes. This semester’s main result concerns the citation step. It gives evidence about being used as an information source, not proof of increased sales.

3. How our system works

Think of our system as giving the AI a reading pack. First, our search code finds travel pages. We save copies so we know which information was used. Then the system prepares a question and numbered page text for the AI. The model receives that information through an API and writes an answer with source references. Our checker reads those references and identifies whether Flight Centre was cited. This is often called retrieval-augmented generation, or RAG: supplying information to help a model answer. We did not train a new model. During the main answer test, the AI did not browse the live web or choose new pages outside the supplied pack.

5. What we tried separately

We explored six approaches before choosing a combined page. Rendering and cleanup expose useful captured information and make it readable. Questions and answers keep related information together. Structured facts organise existing details. External information adds attributed material from outside the page. Schema adds labels intended for software. Automatic rewriting changes the wording more broadly. The tests did not all produce clear gains. Questions and organised facts were encouraging. Rendering and external information had more uncertainty. The schema experiment also changed visible text, so we cannot isolate schema’s effect. The reviewed automatic rewrite performed worse. Exact numbers and intervals remain in the evidence package; this slide summarises what we learned.

6. What we combined

The final page combines a smaller set of compatible changes. We expose captured rendered information, clean up its text, organise supported travel information, and preserve useful question-and-answer relationships. We did not combine every experiment. Added external enrichment, added schema, broad rewriting and moving the whole source to the front stayed separate. Selecting components is a design decision informed by evidence. It does not prove that each component caused a particular share of the final gain. The combined page therefore needed its own test. We can inspect the output and trace it back to the implementation.

7. How a page becomes an AI input

Our implementation has several connected parts. The page-processing code starts from saved content, applies the selected improvements and produces a page output. The cleaner extracts readable text. The experiment code places that text into the same numbered source position used for the baseline. The API sends it with the question and common instruction. We save the resulting answer and its source list together. This matters because a page may look complete in a browser but lose useful information during extraction. Our output checks examine the actual text sent to the model. Detailed file names and the saved model settings are available in the backup material.

10. How we checked the page changes

Before trusting the comparison, we checked three things. First, were we using the correct saved versions? Second, did the final question-restoration change preserve the intended information? Third, did the text sent to the AI match the saved output? We rebuilt the final FAQ stage and matched its saved page outputs. We also checked the Flight Centre text recorded in the selected model inputs against those outputs. This catches mistakes such as displaying one page but testing another. The check has a boundary: it verifies that the implementation did what we intended, not that every inherited travel statement is correct or that a public AI service will behave the same way.

12. Flight Centre was cited more often

The baseline cited Flight Centre in forty percent of the answers. With the selected improved pages, the rate was forty-nine-point-three percent initially and fifty-two-point-four percent when generated again. The exact counts are saved with the evidence. Both runs used the same treatment prompts and sources, but the generated answers differed. We show both rather than treating the higher number as a promise. The main message is that Flight Centre was cited more often in these saved comparisons. It does not mean that the page will receive this rate in every public AI engine or for every customer question.

13. How confident are we?

We did not rely on a single example. We repeated answers and examined how results varied between questions. More question averages improved than declined, but the effect was not universal. We also calculated uncertainty by sampling whole questions, keeping their repeated answers together. The two treatment-versus-baseline intervals were positive in these comparisons. However, the difference between the treatment runs was not clear enough to say the second run was better. Trying multiple versions and reusing an older baseline still limit the conclusion. The detailed calculations remain available for questions, but our interpretation is straightforward: encouraging evidence within the tested setting, not a guaranteed future outcome.

14. Source order also mattered

We separately asked whether the position of a source changes how often it is used. We kept the source text the same and moved the first Flight Centre source to the beginning, preserving the competitors’ relative order. Citation was higher in that test. This tells us the model’s reading order can influence the outcome. It does not show that we improved Flight Centre’s ranking on a search engine, or that Flight Centre can control a public AI engine’s internal source order. This ordering experiment was not part of the final combined page. It is a useful finding about the behaviour of our test environment.

15. What this means for Flight Centre

The delivered value is a working prototype and a way to test page changes using saved evidence. Flight Centre can see which kinds of captured information became clearer and inspect how the AI used it. That supports a practical content-improvement discussion. However, the page must first be available to the AI. Our main comparison does not solve discovery or prove more recommendations and bookings. Any live use would need current product information, content ownership and separate commercial measures. Those are proposed applications, not additional outcomes we claim to have delivered.

16. What this experiment cannot prove

We want the conclusion to be useful without overstating it. The main test supplied the same sources to both conditions; it does not represent every step of a public AI search. In a separate test where retrieval exposure could change, we did not establish a gain. Fresh rewordings also gave a less certain result. Our comparison uses earlier baseline answers and captures from different contexts, and development was informed by earlier results. These facts limit causal certainty and generalisation. A citation also needs a separate human check to establish whether it supports the statement. These limitations do not erase the prototype or observed result; they define what the evidence can support.
