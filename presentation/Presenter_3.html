7. How a page becomes an AI input

Our implementation has several connected parts. The page-processing code starts from saved content, applies the selected improvements and produces a page output. The cleaner extracts readable text. The experiment code places that text into the same numbered source position used for the baseline. The API sends it with the question and common instruction. We save the resulting answer and its source list together. This matters because a page may look complete in a browser but lose useful information during extraction. Our output checks examine the actual text sent to the model. Detailed file names and the saved model settings are available in the backup material.

9. Example: keeping the question with its answer

This example shows a specific implementation problem and our fix. The question lived inside an interactive accordion button. Our common cleaner removed interactive buttons and could remove the question even though the expanded answer remained. The answer then lost its context. The refinement restores an eligible captured question as readable text beside the same answer. It only handles the supported already-expanded sections. Point to the question before and after. This is a clearer example of preserving meaning during extraction: the model should understand what the answer is answering. We checked that this final step preserved the existing answers and offer information.
